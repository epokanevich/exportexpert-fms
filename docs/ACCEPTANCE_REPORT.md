## 5. Что НЕ проверено и почему

- **Превью-деплой Vercel и логи функций** — MCP Vercel без доступа к команде `epokanevichs-projects` (403). Ссылка подтверждения дважды выдана и истекла. Скрипт `vercel-build` проверен по коду: `db push` без `--accept-data-loss`, bootstrap только в пустую базу. Холодный старт и `maxDuration=60` на Vercel вживую не проверены.
- **Локальный запуск на Supabase** — сеть этой машины рвёт TCP до AWS eu-central-1 примерно через 1,5 с (ECONNRESET, тот же эффект описан в README). Бой шёл на локальном PostgreSQL 18 (embedded, порт 5434), а Supabase использовался через MCP для схемы и advisors.
- **Прод Render** — только чтение (редирект без сессии, заголовки, пароль в бандле). На проде не входил и ничего не менял. Боевая база Neon не тронута.
- **Сценарий H** (сброс демо): после исправлений в демо-режиме не перепрогонялся; проверено, что при выключенном режиме сервер отказывает. Двойной клик по сбросу не проверялся.
- **Истёкшая сессия** (8 ч) — время не подменялось. Логика `jwtVerify` с `exp` проверена по коду.
- **Реальные устройства, Safari/Firefox, VoiceOver/TalkBack** — только эмуляция Chrome.
- **`npm audit`** — не запускался.

## 6. Рекомендации на следующий шаг

1. Задеплоить исправления: демо-стенд на Render заработает без настройки, так как демо-режим включён по умолчанию. Для боевого стенда задайте `DEMO_MODE=false` и смените пароли демо-пользователей: сейчас они в README, а UI смены пароля нет.
2. Rate-limit входа и отзыв сессий через Postgres без новой инфраструктуры:
   - таблица `LoginAttempt(key, count, resetAt)` с upsert по ключу IP+email;
   - поле `User.tokenVersion` в JWT, проверка в `authorize()`, инкремент при выходе и смене роли.
3. Денежная модель: деньги в `numeric(12,2)`; история ставок аренды (`LeaseRatePeriod`) вместо запрета смены ставки; частичный уникальный индекс «одна активная операция на контейнер»; soft-delete вместо каскадного удаления истории.
4. Инфраструктура БД: `idle_in_transaction_session_timeout` на Neon-роли; CSP + HSTS в `next.config.ts`; бизнес-часовой пояс для серверного «сегодня» (D-28).
5. Получить решение заказчика по конвенции Free Time (D-20), затем закрыть UX-хвосты: тап-цели ≥ 44 px (D-17), клавиатурный доступ к строкам таблиц (D-22), запрет будущих дат On-Hire (D-19).
