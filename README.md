# FMS «Экспортэксперт» — управление парком собственных контейнеров (SOC)

Fleet Management System для собственного парка контейнеров: реестр с проверкой номеров по ISO 6346, контроль One-Way
(репозиционирование с расчётом детеншна), долгосрочная аренда с историей ставок Per Diem, терминальный инспектор
со смартфона (акты осмотра в кодах CEDEX, фото EIR), дашборд руководителя, аудит-журнал всех операций.

Архитектура и доменная модель: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · История изменений: [CHANGELOG.md](CHANGELOG.md) ·
Отчёт о приёмке: [docs/ACCEPTANCE_REPORT.md](docs/ACCEPTANCE_REPORT.md).

> ## ⚠️ Два режима работы — выберите явно
>
> | | **Боевой режим** (по умолчанию) | **Демо-режим** (`DEMO_MODE=true`) |
> |---|---|---|
> | Пароль на странице входа, «вход в 1 клик» | нет | есть |
> | «Сбросить демо-данные» (стирает базу) | недоступно | доступно администратору |
> | Первый запуск в пустую базу | только администратор из `ADMIN_INITIAL_PASSWORD` | 31 демо-контейнер, 3 демо-пользователя |
>
> **Без переменной `DEMO_MODE` приложение работает в боевом режиме.** Демо-режим включайте только на стенде для показа.

## Быстрый старт (локально)

Требуется Node.js 20.9+ и PostgreSQL 14+ (локальный, Neon, Supabase).

```bash
npm install
cp .env.example .env.local   # DATABASE_URL, AUTH_SECRET (≥ 32 символов), для демо — DEMO_MODE="true"
npm run setup                # миграции (prisma migrate deploy) + демо-данные
npm run dev                  # http://localhost:3000
```

Демо-учётные записи (появляются только при `DEMO_MODE=true` и `npm run setup`/`db:seed`): `admin@exportexpert.ru`,
`manager@exportexpert.ru`, `inspector@exportexpert.ru`, пароль `Export2026!`. На боевом стенде этих пользователей нет.

| Команда | Что делает |
|---|---|
| `npm run dev` | Dev-сервер |
| `npm run build` / `npm start` | Production-сборка и запуск |
| `npm run typecheck` | Проверка типов |
| `npm test` | Unit-тесты (Vitest): деньги, домен, права, CSP, политики |
| `npm run test:int` | Интеграционные тесты на **локальном** PostgreSQL: `TEST_DATABASE_URL=postgresql://…@127.0.0.1:5432/fms_test` (схема пересоздаётся; облачные хосты запрещены) |
| `npm run db:migrate` | Применить миграции (`scripts/migrate-deploy.ts`, с baseline для баз из `db push`) |
| `npm run db:seed` | Перезалить демо-данные (очищает доменные таблицы — только для демо/разработки) |
| `npm run db:bootstrap` | Первый запуск: демо или администратор — **только в пустую базу** |

## Боевой режим

1. Переменные окружения (полный список и пояснения — [.env.example](.env.example)):

   | Переменная | Обязательно | Значение |
   |---|---|---|
   | `DATABASE_URL` | да | PostgreSQL (Neon — pooled-хост и `sslmode=require`) |
   | `AUTH_SECRET` | да | случайная строка ≥ 32 символов: `node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"` |
   | `ADMIN_INITIAL_PASSWORD` | для пустой базы | пароль первого администратора (≥ 10 символов); `ADMIN_EMAIL` — по умолчанию `admin@exportexpert.ru` |
   | `DEMO_MODE` | нет | **не задавайте** |
   | `BUSINESS_TIMEZONE` | нет | часовой пояс компании (IANA), по умолчанию `Europe/Moscow` |
   | `ATTACHMENTS_DRIVER` | нет | `db` (по умолчанию в production — файлы в PostgreSQL) или `local` (диск, только для разработки) |
   | `TRUSTED_PROXY_HOPS` | нет | число доверенных прокси перед приложением; Render/Vercel — `1` |

2. Первый вход — под администратором из `ADMIN_INITIAL_PASSWORD`, сразу **Профиль → Сменить пароль**.
   Остальных сотрудников заводит администратор: **Пользователи и аудит → Новый пользователь** (роли ADMIN / MANAGER / INSPECTOR).
3. Роли: **ADMIN** — всё, включая списание, пользователей и аудит; **MANAGER** — реестр, One-Way, аренда, осмотр;
   **INSPECTOR** — только терминал: осмотр, Gate-In/Out, КБК, вложения.
4. Безопасность: сессия JWT 8 ч в httpOnly-cookie с версией (выход, смена роли или пароля отзывают все сессии пользователя),
   лимит входа 5 ошибок / 15 мин на IP + email в PostgreSQL, CSP с nonce, HSTS, аудит каждой операции.

### Что показать (сценарии демо)

Все даты демо-данных считаются от дня загрузки сида — сразу после загрузки или сброса сценарии совпадают с описанием.

- **Дашборд** — 31 контейнер / 50 TEU, утилизация 64,5 %, горящие и просроченные One-Way, аренда $/мес, алерты (КБК, ремонт, простой).
- **One-Way** — 8 активных рейсов: 2 просрочены (EXPU 402918, FESU 518204 — детеншн капает), открытая претензия (FESU 516877).
  Gate-In с предпросмотром детеншна; при повреждении — претензия (DISPUTE). Печатный Release Order.
- **Аренда** — 4 договора: LC-2026/003 истекает через 10 дней (продлите с новой ставкой — история ставок сохранит прежнюю
  для уже прошедших дней), LC-2026/007 — задолженность. Договор с будущей датой On-Hire получает статус «Ожидает On-Hire».
- **Реестр** — серверный поиск по подстроке номера (`2918`), фильтры, сортировка, пагинация, фильтр «Списанные»,
  добавление контейнера с живой проверкой ISO 6346 («Подставить» исправляет контрольную цифру), CSV всей выборки.
- **Инспектор** (телефон) — найдите `9930`, нажмите «Исправен»: ремонт закроется, EOR уйдёт в затраты. Акт «Поврежден»
  принимает строки CEDEX (место, узел, повреждение, ремонт, стоимость), к событию можно прикрепить фото EIR / PDF.
- **Блокировка по КБК** — EXPU 401890-2 исправен, но табличка просрочена: выдача и Gate-Out запрещены, сервер отклоняет подделанный запрос.

## Инструменты логиста

- **Excel / CSV** — реестр (вся выборка по фильтрам, на сервере), One-Way и аренда: UTF-8 с BOM, `;`, десятичная запятая,
  защита от формула-инъекций.
- **Release Order** — документ A4 с Free Time, последним бесплатным днём, ставкой детеншна и примерами начисления; «Печать / PDF».
- **Вложения** — PNG / JPEG / PDF до 5 МБ к любому событию журнала; тип проверяется по содержимому файла; выдача только по сессии.

## Бизнес-правила (выдержка)

- Номер контейнера: 4 буквы (4-я — категория U/J/Z) + 6 цифр + контрольная цифра ISO 6346.
- Деньги — `numeric(12,2)`, арифметика в центах, округление до цента «от нуля» (`src/lib/money.ts`).
- Free Time: **день Gate-Out = день 1** (отраслевая норма, утверждена 27.10.2026): последний бесплатный день = выдача + N − 1.
  Он сохраняется в рейсе при выдаче и печатается в Release Order, поэтому смена правила (`FREE_TIME_CONVENTION`) не трогает
  выданные рейсы. Детеншн = сутки после последнего бесплатного дня × ставка, включая день Gate-In.
- Аренда: дни On-Hire … накануне Off-Hire, каждый день — по ставке, действовавшей в этот день (`LeaseRatePeriod`).
- «Сегодня» для просрочек, начислений и дашборда — по `BUSINESS_TIMEZONE`; дата операции не может быть позже текущей даты во Владивостоке.
- Списание — мягкое (статус «Списан» + дата), история и договоры сохраняются; физическое удаление запрещено на уровне БД.
- Тех. статус, грейд, EOR и срок КБК меняются только актом осмотра / продлением КБК (не правкой карточки).

## Деплой на Render

Web Service (Node) + PostgreSQL в Neon.

| Параметр | Значение |
|---|---|
| Build Command | `npm install && npm run render-build` |
| Start Command | `npm run start` |

`render-build` = `prisma generate → scripts/migrate-deploy.ts → prisma/bootstrap.ts → next build`:

- **миграции**, а не `db push`: база, созданная раньше через `db push` (таблицы есть, истории миграций нет), автоматически
  получает baseline `0_init`, затем применяются остальные миграции. Ни одна миграция не удаляет данные;
- **bootstrap только в пустую базу**: при `DEMO_MODE=true` — демо-данные, иначе — администратор из `ADMIN_INITIAL_PASSWORD`;
  повторные деплои ничего не загружают.

**Перед первым деплоем этой версии на существующую базу** выполните read-only проверку
[`scripts/preflight-prod.sql`](scripts/preflight-prod.sql) (SQL-редактор Neon или `psql "$DATABASE_URL" -f scripts/preflight-prod.sql`)
и сделайте снимок (Neon → Branches → Create branch). Все проверки должны вернуть 0 строк: иначе миграция с ограничениями
откатится и деплой остановится. Подробности — [docs/DEPLOY.md](docs/DEPLOY.md).

> **Демо-стенд на Render:** начиная с этой версии демо-режим по умолчанию выключен. Чтобы стенд для проверяющих остался
> демо, перед деплоем задайте в Render → Environment `DEMO_MODE=true`.

## Деплой на Vercel (альтернатива)

Те же переменные окружения; Vercel вызывает `vercel-build` (тот же конвейер, что `render-build`). Тело запроса функции
ограничено 4,5 МБ — для вложений до 5 МБ на Vercel используйте Render или добавьте драйвер хранилища с прямой загрузкой (см. ARCHITECTURE).

> **Сетевое ограничение.** Из некоторых сетей TLS-соединения с AWS (Neon, Supabase) обрываются через несколько секунд.
> Это не ошибка приложения: выполняйте миграции из CI/сервера или просто задеплойте — они выполнятся на стороне хостинга.
